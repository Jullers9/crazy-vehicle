## Что получает разработчик

- CHANGELOG.md — первая заморозка и порядок последующих изменений.

## Работа разработчика

1. Прочитать SPEC, TCS и tests/README.md. Python 3.10+, сторонние пакеты для тестов не нужны. Если `python` открывает Microsoft Store, установить Python и убедиться, что команда доступна в PATH, либо использовать полный путь к интерпретатору.
2. Создать в корне walking_plane.py с WalkingPlane и экспортируемыми исключениями по SPEC. Внутреннее устройство свободное, тестовый пилот частью реализации не является.
3. Создать README.md с требованиями, примером использования и командой запуска тестов. Вести BUGREPORT.md: фиксировать все вопросы и спорные проверки; если вопросов нет, явно указать это.
4. Из корня выполнить `python -m unittest discover -s tests -t . -v`. После появления интерфейса должны обнаруживаться все 20 тестов; добиться их прохождения и передать результат автору.
5. SPEC, TCS и тесты самостоятельно не менять. Вопросы передавать через BUGREPORT.md; изменения автора после заморозки — через CHANGELOG.md и regression-тест, существенные изменения ТЗ — с повторным ревью.
