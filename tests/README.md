# Тесты контракта «Топота»

Требуется Python 3.10+; сторонних пакетов нет. Запускать из корня проекта:

```bash
python -m unittest discover -s tests -t . -v
```

- `test_walking_plane.py`: TC-01…TC-16, модульные проверки AAA.
- `test_scenarios.py`: TC-17…TC-20, маршруты GWT.
- `pilot.py`: команды пилота; только делегирование публичным методам.
- `support.py`: доменные утверждения о состоянии, времени и отказе без изменений.

Реализация `walking_plane.py` относится к роли D и сейчас отсутствует. До её появления обнаружение тестов завершается двумя ошибками импорта тестовых модулей с `ModuleNotFoundError: No module named 'walking_plane'`. Это ожидаемая начальная RED-стадия; она не подтверждает корректность всех проверок поведения. После появления интерфейса нужно убедиться, что обнаружены все 20 тестов, и анализировать каждое падение.

Не использовать skip/expectedFailure для сокрытия отсутствующей реализации. Тесты не обращаются к приватным полям и не предписывают устройство реализации. Изменения после заморозки проводит автор через CHANGELOG.md с regression-тестом; вопросы разработчика оформляются в BUGREPORT.md.


Замороженная версия контракта: 1.0 от 8 ноября 2026 года. Решения по ревью зафиксированы в RESPONSES.md, история контракта — в CHANGELOG.md. Допуск `1e-7` для результатов и правило достаточности энергии определены в SPEC 3.1; точное сравнение снимков до/после отказа проверяет отсутствие любых изменений, а не приближённое соответствие ожидаемому результату.

Разработчик создаёт в корне walking_plane.py, README.md с примером использования и инструкцией запуска, а также ведёт BUGREPORT.md для вопросов к контракту. SPEC.md, TEST_CASES.md и тесты разработчик самостоятельно не меняет. После реализации результат передаётся автору для приёмки.
